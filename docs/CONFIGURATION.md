# Конфигурация TMC StaffWork 0.1

Основной файл — `plugins/TMCStaffWork/config.yml`, локализация — `messages_ru.yml`. Все изменения YAML выполняйте при остановленном сервере либо применяйте `/sw reload`, если параметр допускает горячую замену.

## Общие параметры

- `config-version` — служебная версия структуры;
- `general.server-id` — идентификатор узла в общей БД, только латинские буквы, цифры, `_` и `-`;
- `general.time-zone` — IANA-часовой пояс, например `Europe/Moscow` или `UTC`.

## Хранилище

- `storage.type` — `YAML`, `SQLITE`, `H2` либо `MYSQL`;
- `storage.pool.maximum-size` — размер пула JDBC от 1 до 30;
- `storage.pool.connection-timeout-ms` — ожидание подключения от 1000 до 60000 мс;
- `storage.mysql.*` — адрес, порт, база, пользователь и пароль.

Тип БД нельзя безопасно сменить через reload. Перезапуск обязателен. Перед ручной миграцией остановите сервер и сделайте резервную копию.

## Ранги

Ключи `ranks` — стабильные внутренние идентификаторы длиной до 32 символов. Допустимы `[a-z0-9_-]`. Отображаемое имя можно использовать в будущих интерфейсах; команды и БД сохраняют идентификатор.

## Учёт времени

`work-time.counted-statuses` перечисляет статусы, которые входят в статистику. Изменение применяется командой reload и влияет на расчёт всей истории, потому что исходные интервалы сохраняются без потери.

## Автоматизация

- `automation.join.auto-start-session` — открывать сессию сотруднику при входе;
- `automation.join.status` — статус после автоматического старта;
- `automation.quit.behavior` — `STOP`, `PAUSE` или `KEEP`;
- `automation.afk.threshold-seconds` — порог 30–86400 секунд;
- `automation.afk.return-on-activity` — возвращать из AFK в `WORKING`.

`PAUSE` переводит активную сессию в `BREAK`; `KEEP` оставляет интервал открытым. Для большинства одиночных серверов безопаснее `STOP`.

## PlaceholderAPI

`placeholder-api.status-colors` задаёт legacy-префиксы для внешних потребителей PlaceholderAPI. Используйте `&a`, `&e`, `&c`, `&7` либо совместимые значения. Локализованные сообщения используют MiniMessage и настраиваются отдельно.

## Telegram

- `enabled` — включение интеграции;
- `bot-token` — секрет BotFather, хранится только на сервере;
- `polling-seconds` — пауза между циклами polling;
- `link-code-ttl-seconds` — срок действия кода;
- `request-cooldown-seconds` — ограничение выдачи кодов;
- `events` — разрешённые уведомления;
- `templates` — тексты с плейсхолдером `{player}`.

Reload безопасно перезапускает Telegram-клиент с новыми параметрами. Токен никогда не включается в стандартный конфиг репозитория и не логируется.
